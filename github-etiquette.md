# Some Basic Rules/Tips for our Github Org Page

🚧👷‍♂️ SITE STILL UNDERGOING CONSTRUCTION 👷‍♂️🚧
*not listed in order of importance*

1. Write scripts in your personal folder (repo), unless you are working in teams.
2. While working in shared repos, please create a branch to form new commits/changes before pushing to main repo!
3. When committing changes, please write meaningful messages that are detailed and informative.
    - example of good commit: 'git commit -m "created a ggplot for sperm motility data"'
    - example of bad commit: 'git commit -m "made changes"'
    - note: 'git commit -m "message"' commands ONLY make changes to local repository, and not remote repository on github.
    - note: to commit changes to remote, be sure to write the note "git push origin main". If you are working on a branch, it would be
      "git push origin <branch>" 
    - tip: it's good to make frequent commits to check versions of your file changes over a period of time. 
4. Use "git status" *frequently*. This will tell you what changes are pending or unstaged, so that you don't muddy your branches.
5. Include a ReadMe per repository! This is part of good practice, and will give people who may view or repository a brief overview of
   what your project covers. READMEs also tend to come with installation or navigation instructions as to what is included in your
   scripts.
6. Upload repositories per PROJECT, not per person.
